# Wonder decision repair and expanded proof allowance

The first full-proof trial physically injected missing motor-running feedback. M8 reported fault 12, removed its motor command and lit red. Wonder then selected a new pending-route-offer/reset/restart investigation from the actual fault observations. That second decision put a truth-only record in public completion evidence and changed an immutable experiment definition. The runtime rejected it before applying any actions. Its 11 proposed PLC claims match the original records, but the finding and follow-up were never accepted/executed. This remains partial evidence. `audit-fault-trial.mjs` reconstructs 3,885 hash-chained events, checks raw responses/lineage/exact results and verifies the independent recorded recovery.

The corrected contract distinguishes public completion evidence from `finding.injectedTruthRefs`, explains immutable experiments and reports effect-free validation errors back to Wonder. Repair is opt-in (`maxRejectedDecisions`, default 0, maximum 3). A returned invalid decision may receive a new model turn only when validation appended no ledger event, the revision is unchanged, its decision lease finished validly, the campaign is running and the driver is healthy. The next turn uses a fresh hold lease and preserves provider response/tool lineage. It receives `previousDecisionRefusal`, empty results for the rejected call and current observations. Every correction consumes an ordinary paid reservation and turn. A partial plan/action, uncertain write, failed lease, connector fault or cancellation stops as before. Identical repeated decisions and provider/service retry limits remain separate.

The engineer authorized the available $150 Meta credit pool and removed the former $12 financial boundary. Twelve historical conservative one-dollar reservations remain immutable; they are not an invoice or the user's reported ~$7 actual billing. Explicit factory `proofAllowance` now permits up to 40 requests, a configured session ceiling up to $150 and a $1–$5 integer conservative per-request admission. Default configuration remains four provider calls, $1/request and a $15 durable session. Durable logs accept old and new reservation sizes, sum them exactly, flush each charge and retain failed/uncertain attempts. Token preflight uses the exact generation instructions and refuses a request whose maximum uncached token cost exceeds its configured reservation.

The prepared next campaign configuration is 20 decisions, 16K output/high reasoning, $3 conservative/request, at most two eligible 503 retries and three effect-free corrections inside those turns. The durable session ceiling matches the authorized $150 credit pool; this campaign permits at most $60 of new conservative reservations. Finish when proof is sufficient; do not consume the allowance for its own sake. These values are operational bounds, not a new financial approval requirement. The PLC, generated world, connector, scan/commit path and child timing code are unchanged. A new source-bound build and fresh zero-model commissioning are required before this code is live.

Validation uses `scripts/check-w4-decision-repair.js`: typecheck, full runtime/browser tests, separate network-disabled decision-repair/accounting cases and wrapper regressions. Exact source hashes, the historical live pin's 639 unchanged file hashes and unchanged shared accounting are checked. Live qualification and a complete fault-plus-adaptive verdict must be recorded separately; offline tests cannot establish either.
