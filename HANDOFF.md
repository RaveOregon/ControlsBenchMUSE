# ControlsBench Muse — cross-computer handoff

Updated 2026-10-29. Read this before extending the prototype. The user wants a useful Meta hackathon slice, not a polished production conveyor or a large architecture exercise.

## Product promise and current decisions

- The hackathon entry is **Indie Developer** under **Build for Your World**. The durable event, judging, technical-resource, rights/provenance, and submission brief is `docs/hackathon-brief.md`. The submission deadline is 2026-11-04 at 9:00 PM ET; the repository must be public and the submission requires an accessible three-minute demo video.
- `docs/architecture-decisions.md` is the live pre-build decision register. It separates settled decisions, provisional recommendations, and unresolved questions. Read it before implementing the world runtime, and do not silently treat provisional choices as accepted.
- The flagship is **Muse-authored, continuous, closed-loop bench testing of actual running PLC logic**. An engineer provides a functional spec and signal information. Muse creates the external process behavior and experiments, drives simulated conditions, observes real PLC outputs, investigates surprises, and reports evidence. A hand-built simulator plus a static AI test list does not satisfy the goal.
- CODESYS Control Win is the first PLC target; its IDE/runtime is **not currently available**, so do not claim live PLC integration yet. OPC UA is the first workstation transport. A vendor-specific PLC-side interceptor selects hardware passthrough by default and simulation deliberately.
- Simulation must cut in at the raw hardware/device image, not at already-normalized engineering values. The workstation may model physical truth in engineering units, but it supplies booleans, encoder counts/pulses, raw analog integers, words, or device fields as the PLC would actually receive them. This preserves scaling, filtering, rollover, encoding, and input-conditioning logic as part of what is tested.
- The current architecture **requires an editable/rebuildable PLC project** so a vendor-specific ControlsBench interceptor library can be inserted at the raw I/O boundary. An untouched compiled/protected controller is not supported. Do not confuse required integration access with machine-readable source access for Muse: after installation, campaigns run from the configured signal contract and observed behavior even when the IDE offers no MCP or useful source export. Do not scope-creep into generic PLC source review; source is useful only when conveniently accessible and tied to a behavior already demonstrated through the connected bench.
- The preferred interceptor pattern is controls-engineer-installed and type-oriented: DI, AI, DO, and AO blocks immediately around the raw I/O image. They pass hardware values/commands through unchanged by default and select or expose the simulated raw image in simulation mode. Allow vendor-specific device, assembly, module, or per-signal variants when a platform cannot support centralized type wrappers.
- The first generated world is a continuous, spatially coherent conveyor model rather than a logical event script. Muse should infer believable geometry, carton motion, sensor zones, actuator motion, runout, and raw encoder/device behavior and show its assumptions. Use only a lightweight SVG/Canvas diagnostic schematic; do not build generated renderer code, a scene editor, or a general graphics/3D/CAD engine. Testing, adaptive control, trace, and evidence take priority.
- The hackathon demo machine baseline is accepted: one conveyor lane, two sequential diverts (A/B), and straight runout. Unassigned cartons normally run out; an A/B carton reaching runout is a misroute; Stop immediately stops belt and new feed. The user accepted the proposed defaults in `docs/conveyor-machine-spec.md` for the demo and does not want further perfection of fictional machine details.
- The user owns Machine Agent (`RaveOregon/industrialintelligence`) and HMaI; selective reuse is authorized. Do not copy either project wholesale. The old separate ControlsBench project is unrelated.
- HMI/screen **video can be recorded concurrently with a test**, timestamped with the I/O trace, and analyzed by Muse in clips. Screen observation is valuable even if visual UI control is deferred. Video-model calls do not belong in the PLC scan loop.
- This repository is **private for now**. Public hackathon publication and any license are later decisions; do not invent a license.
- Muse Wonder 1.0 in Standard mode is the primary product model for the first slice. `docs/model-selection.md` records the direct Wonder-versus-Spark comparison and decision. Keep the model configurable, but do not add routing complexity before the complete workflow works.
- Do not make the agent timid merely because conventional guidance favors narrow allowlists. The bench is sequestered, so Muse should have broad authority over the simulated process, generated experiment code, resets, branching, and fault creation. Preserve DUT immutability, logging, snapshots, and hard-timed execution for experimental validity. `docs/frontier-roadmap.md` records the local Glimmer, high-autonomy, and adaptive-weight tracks to investigate during the hackathon as time permits.
- The generated world is **code-primary and contract-wrapped**. A structured manifest declares raw signals, parameters, state, devices, assumptions, and evidence obligations; Muse-generated TypeScript is the single source of truth for behavior. All PLC-facing effects flow through the instrumented workstation context and execution coordinator. Do not replace this with a restrictive custom behavior IR.
- Generated code is Muse's workshop, not a new controls-engineer maintenance task. The normal UI shows an expandable campaign plan grouped into engineering checks (I/O, startup/modes, functional, runtime/timing, alarms/faults/recovery, normal operation, edge/stress, and adaptive investigations). Engineers steer scope and intent rather than repairing TypeScript.
- **Start Campaign** is the single authorization for the selected scope. Muse may execute checks, inject simulated faults, branch, and add adaptive investigations without per-test approvals. The engineer retains Pause, Stop, and natural-language steering; physical-output suppression remains engineer configuration.
- The workspace must show truthful Codex/Kiro-style updating activity text grounded in model, coordinator, connector, tool, and PLC events. Show what Muse is doing or awaiting, elapsed time, last activity, and distinguish slow reasoning from a stalled agent, runtime, connector, or PLC link. Pause holds the current image; Stop finalizes and holds for inspection; Reset zeros inputs while staying simulated; Exit Simulation deliberately returns to hardware.
